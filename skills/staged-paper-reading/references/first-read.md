# 标题、摘要和结论精读指南

在第一次阅读使用本文件。输出禁用原文页码、页数及页码范围备注，必要定位使用章节、公式号或图表号；普通小节标题后不留空行，正文末尾保留一行空行。Markdown 表格前保留一行空行；表格后仍有正文说明时，也保留一行空行作为块边界，避免说明被解析成额外表格行；表格后直接接下一图表标题时不补空行。 聊天说明采用“阅读讲解格式（聊天）”；首次精读完整保存到累计 Markdown，立即按“完整阅读 Markdown 格式（文件）”使用美元定界符和红色重点。

## 标题和作者

- 给出标题原文与自然的中文译法。
- 提取研究对象、任务和关键词。解释标题是在提出方法、报告发现、主张某种观点，还是介绍综述。
- 对夸张或高度概括的标题，说明它在论文任务和架构中的具体含义及边界。
- 根据原文列出作者并保留等贡献、共同第一作者、随机排序等必要说明。
- 仅对影响力有可核实依据、且其背景有助理解本研究的作者做简短介绍。说明代表工作或本文贡献，避免凭机构名、姓名印象或署名顺序下判断。
- 以论文里的贡献说明和公开的一手资料为依据。介绍当前职位等会变化的信息时核实日期；无法核实时省略该部分。
- 作者段落保持简短，把主要篇幅留给摘要和结论。

## 摘要精读

按原文顺序，将摘要拆成句子或语义单元。对每个单元：

1. 标明它的作用：背景、研究缺口、方法、结果、意义或适用条件。
2. 用准确中文转述，解释关键术语，并指出它与前一个单元的逻辑关系。
3. 说明作者实际提出或验证了什么，保留条件、比较对象和关键数字。
4. 解释理解该句所必需的背景；不提前展开整章方法或图表。

再提取四要素：

| 要素 | 必须回答的问题 |
|---|---|
| 问题 | 具体任务是什么？此前有什么困难或不足？ |
| 方法 | 核心设计是什么？与此前做法的区别是什么？ |
| 结果 | 在什么任务、数据或条件下，观察到了什么结果？ |
| 意义 | 结果为什么有价值？这项意义是原文明说还是合理推断？ |

没有某项要素时如实说明，不能为了填表捏造内容。摘要里的“更快”“更好”“更少”等比较必须带上适用范围。把“本文提出的新组合”与“发明了已有组件”区分开。

## 结论精读

- 先确认明确的结论章节名称与位置。
- 按段落或论点解释：完成了什么、证据支持什么、在哪些条件下成立、有哪些限制、下一步是什么。
- 检查结论与摘要是否一致，有没有新增或扩大主张。
- 区分已验证结果、作者计划和讲解者分析。未来方向不能当作本论文已经完成的工作。
- 作者没有列限制时明确说明，不自行把推测的不足归给作者。
- 没有 Conclusion 或由其他章节代替时，按 SKILL.md 的未决选择规则询问用户，再决定读候选部分还是跳过。

## 最后的比喻

按需选择一个生活或动漫情境，对应论文的问题和解决思路：

- 场景里的困难，对应论文要解决的问题。
- 场景里的新做法，对应论文核心机制。
- 场景里的改善，对应论文已展示的结果。
- 解释比喻不能覆盖的地方，避免让读者把类比当作实现细节。

## 回答顺序

第一次阅读 → 标题与作者 → 摘要逐句或分单元精读 → 四要素 → 结论精读 → 按需给一个形象比喻 → 完成状态与两个正文详细阅读选择。

遇到结论替代或材料缺失选择时，先把已完成内容保存到固定文件并交付链接，再提出未决问题；尚未完成第一次阅读，不提出阶段末尾两个选择。获得回复后补完本阶段，不重做已有精读。

## 阶段末尾的两个选择

完整内容先按 reading-markdown.md 保存到本轮同一文件，交付链接；使用按 choices-and-waiting.md 预先核对的全部正文图表和公式清单，排除附录与独立补充材料。说明“第一次阅读完成”，同时提出：

1. 是否需要详细阅读正文图表？正文图与表总数不超过 5 时默认是。
2. 是否需要详细推导正文公式？正文公式总数不超过 5 时默认是。

分别报告计数、默认值与范围，允许用户明确否定默认。超过 5 或计数不确定时等待明确选择；这两个问题没有一分钟默认否。到此结束，不输出独立的第一次阅读图表阶段，也不提前展开第二次阅读。未解决结论替代选择时不能先提出已完成状态。
