# 正文精读、剩余阅读与总结指南

用于第二次阅读、可选剩余阅读、循环答疑与通篇总结。所有完整讲解逐阶段保存到本轮固定 reading_md_path，立即遵循文件公式、红色重点、标题和空行要求；聊天说明使用聊天格式。全文不输出原文页码、页数或范围，不另生成精简笔记。

## 正文精读前的符号与参数表

先按 notation.md 建立理解正文主线所需的重点符号与参数含义表，作为 Second Time 首节 `## 1.Notation & Parameters`。通常约 10–20 项，以核心变量、关键分布、模型/算法参数、主要超参数和必要算子为主，采用“符号/参数、含义与作用、关键设定/约束”三列。类型、形状、单位及定位仅在必要时补充；同名不同义分开。局部或附录独有的次要符号在对应内容中解释，不展开全量登记。先保存至固定 reading_md_path 并交付表，再开始正文精读；不另建符号表或第二次阅读文件，不额外询问是否进入正文。
符号表不是附录逐节阅读或全部推导，不改变图表/公式选择及附录默认范围；无公式时如实说明。不宣称表格覆盖全部符号；后续只把影响主线的新符号或关键歧义补入同一表，其他符号就地解释，不降低正文精读或所选公式推导的完整性。

## 第二次阅读的范围与组织

- 确认第一次阅读末尾的两个选择分别已解决，列出正文非实验章节、排除的实验/附录范围及选中图表/公式任务。
- 按真实章节顺序精读引言至独立实验、评测或实证结果章之前，包含此前训练、实现和系统设计章节。实验章之后独立的非实验讨论、分析、限制等继续精读，以覆盖全部正文非实验部分。
- 无独立实证评测章时精读到结论之前；没有结论则到正文结束。方法中的零散实验不是提前停止点，理论 Results 不能直接当实验边界。混合结构按 structure-adaptation.md 处理。
- 第一次阅读已精读的结论核对后回指，不机械重复。参考文献、致谢、附录和独立补充材料不在默认正文精读范围。
- 图表选择为是时按 figures-and-tables.md 详解所有正文图表；单独集中解读时，相关正文位置添加跳转到精读条目的同文件链接，锚点按 reading-markdown.md 核对；公式选择为是时按 formula-derivation.md 推导全部正文公式。正文实验章的所选任务也必须完成，可在同次文件交付的本阶段末尾集中处理，不自动扩展为整章实验速读。
- 用户拒绝系统图表/公式详解时仍解释精读必需的证据、公式直觉和符号，但不将拒绝的任务偷偷全量执行。
- 全部正文 Algorithm、算法框及实质性伪代码按 [Algorithm 详解指南](algorithms.md)详细解释，包含实验章，与图表/公式选择独立。在 Second Time 后部设 Algorithms 集中区，正文实际讲到算法的位置添加指向唯一详解锚点的链接；实验章算法同次完成，只补必要上下文，不自动展开整个实验章。

当前完整讲解写入累计文件的 `# Second Time` 分组；章节与重要小节使用论文实际英文标题的编号二级标题，符号表占第 1 节，正文从 `## 2.Introduction` 等实际标题接续，按输出顺序连续编号，非英文原标题译为英文，中文释义和原文章节编号放正文。后续补充阅读与详细答疑也归入 Second Time，新增章节继续编号；重解释同一章节可以引用其已建立标题，不为同一内容制造冲突编号。

## 正文精读深度

按章节逐步讲解，不用每章几句摘要代替精读，也不强制固定段数。根据重要小节、段落论点或语义单元展开：

1. 解释作者在解决什么问题、为何设置这一部分，连接前后章。
2. 还原论证链：背景、假设、设计动机、机制、证据、结论以及适用条件。
3. 解释关键术语、模块输入处理输出、数据/控制流、训练与推理区别和必要资源设置。
4. 区分作者声称、已支持事实与讲解者补充；说明未交代的信息与潜在边界。
5. 结束本章时提炼要点及下一部分的连接，但不在章节间等待“下一章”。

章节功能侧重点：

- Introduction：逐步解释背景、困难、研究缺口与贡献，比较性主张保留条件。
- Background / Related Work：解释直接相关的先行方法与继承、差别；不把作者对前人的评价视为已核实事实。
- Method / Architecture / Algorithm：整体结构后逐模块、步骤讲解，说明必要损失、训练、推理与算法条件，区分新模块和已有组件。
- Analysis / Theory：解释问题、假设、定理、证据或证明链和结论边界。公式详推选是时执行全部正文公式推导；选否时仍解释理解定理和方法必需的符号与直觉，不自动展开所有形式化细节。
- Training / Implementation / System Design：解释设置为何需要、怎样运行、依赖什么条件及资源；独立实验章之前的这些内容不能遗漏。
- Discussion / Limitations 等正文非实验部分：解释结果的含义、适用范围、作者承认的限制与未来工作，包含位于实验章后的独立章节。

正常在同次文件交付中完成全部正文精读、全部正文 Algorithm 详解及选中任务，核对章节、图表、公式、算法覆盖和算法正文跳转。算法详解逐步覆盖输入输出、初始化、循环分支、状态更新、终止条件及方法作用，并保留原文符号。缺失或实际长度限制时明确未完成内容与续答安排，不宣称完成，不设置任意数量筛选。

## 剩余实验与附录速读

第二次阅读完整结束、内容保存到同一文件并交付链接后询问“是否需要阅读剩下部分？”，按 choices-and-waiting.md 实际等待 60 秒。明确否或真实超时默认否时直接通篇总结；为是时：

- 按原文顺序速读尚未展开的实验、评测、附录及已提供独立补充材料，每个部分说明研究或证明目的、设置/结构、主要结论及边界。
- 实验解释数据与任务、指标方向、比较协议、关键结果、消融和例外；重点说明这一部分验证了什么，不逐项复刻完整实验表。
- 附录解释各部分作用，例如补充证明、实现、设置、额外实验或失败案例，以及得到什么结论；无结论的说明性部分写清用途，不能硬编结论。
- 已详解的正文图表、Algorithm 或已推导公式引用编号及已有详解链接并补充上下文，不重复全部。附录默认速读，不自动逐图详解、逐公式推导或详解全部附录算法；用户指定算法时按 algorithms.md 详细解释并写入同一文件。
- 已在第二次阅读完整精读的混合章节不再次速读。没有实验、附录或其他剩余材料时说明实际情况，不虚构内容。
- 无法取得的材料说明范围，不能假称读完未提供的补充材料。

## 循环详细答疑

剩余阅读完成并保存完整内容到同一文件、交付链接后询问“还有哪部分需要详细解释？”，按 choices-and-waiting.md 实际等待 60 秒。

- 用户指定内容：详细解释相应章节、公式、证明、实验、正文或附录图表，可引用已读内容，按需要使用图表与公式指南。
- 用户指出多个部分时全部处理；没有明确指出范围时澄清，不擅自选择。必要材料缺失时说明并请求材料，不能编造。
- 完成后将完整答疑追加到同一 Markdown，交付链接，再次询问同一问题，重新计时，循环至明确否定或该轮真实超时。每次解释的格式、证据和准确性要求不变，不设任意轮数上限。
- 途中追问或要求修改时先解决当前内容，未完成前不启动下一轮计时。
- 环境无法实时等待时按等待指南保存状态，不假称超时。

## 通篇总结

完整总结追加到同一文件的 `# Overall Review` 分组。先复查完整可访问原文的实验或证明、消融、限制与结论；即使用户跳过剩余阅读，也要核对评价需要的证据，区分内部核对与已经交付的解读。

| 评价面向 | 应回答什么 | 证据要求 |
|---|---|---|
| 主要贡献 | 核心新增内容，通常 1–2 点 | 方法或结果定位，已有组件不能都算创新 |
| 技术优点 | 哪些设计有价值、为什么 | 连接机制、对照、分析或证明 |
| 潜在不足 | 已知限制、缺少验证与可能问题 | 区分原文承认、证据显示、尚待检验 |
| 相关工作定位 | 与前人继承、区别或竞争关系 | 依据论文或核实的一手工作 |
| 启发与延伸 | 值得继续验证的方向与动机 | 设想不能写成已取得结果 |
| 适合谁读 | 背景、阅读或实践目标 | 结合实际门槛和任务 |

以“问题→方法→证据→适用边界”贯穿总结，整合已完成的精读、详解与答疑。没有某类实验不等于方法无效。默认不做复现；详细复现计划、代码实现、额外数学推导或阅读任务只在用户需要时扩展。

总结完成后按 reading-markdown.md 核对并交付同一完整阅读文件，不再另生成精简笔记，也不等待一次“继续”。逐句摘要、正文精读、公式推导与图表详解均完整保留，不为收尾压缩为短条目。
