# 完整阅读 Markdown 指南

从第一次阅读开始执行，适用于后续正文精读、图表与公式详解、剩余阅读、每轮详细答疑及通篇总结。每篇论文的当前版本默认只维护一份累计完整文件，不生成额外精简笔记或分阶段副本。用户明确跳读时，直接按所选阶段开展并初始化同一文件，不为凑齐三个分组补写未读内容。

## 文件生命周期

1. 首次实际开展阅读时只初始化一次文件（默认第一次阅读；用户明确跳读时在所选阶段），将绝对路径记录为 reading_md_path，记录是否已经创建。用户指定位置优先，否则使用当前输出目录；新建时避开无关同名文件。已有本轮同篇同版本文件则恢复记录并继续更新；后续每次写入必须核对目标绝对路径等于 reading_md_path，第二次阅读、符号表、补充阅读、答疑和收尾只能更新此路径。
2. 每阶段先完成阅读内容，按 SKILL.md 的“默认写作 skill”规则应用 anti-defensive-writing 并完成文字检查，再写入同一文件，核对成功后交付同一链接、简短说明和下一问题；篇幅短也必须保存。不能把文件作为聊天过长时的应急导出。
3. 第二次阅读的全部章节、全部正文 Algorithm 详解、所选全部图表和公式放在本次文件交付中，不逐章暂停。必要时可以分批内部写入同一文件；实际交付仍保持阶段完整，未完成内容明确记录，不用长度限制筛选任务。
4. 可选剩余阅读与每轮答疑追加到 Second Time，英文二级章节沿用该组连续编号。相关补充可就地增加或修订，修正旧解释时同步更新，不能保留相互矛盾的结论。
5. 通篇总结追加到 Overall Review，核对整个文件后交付并标记完成。取消独立“精简笔记”生成步骤，不再复制一份摘要版文件。
6. 用户后续修改直接更新固定路径，不重启阶段。恢复上下文先找回记录或已交付链接，不能以长文、分批写入、预览或丢失上下文为由创建另一阅读 MD；原文件丢失时核对记录并恢复至原路径。用户更换论文时为新论文单独初始化；同篇同版本只有用户明确指定新文件或更换版本才重新初始化，无法确定原路径时澄清。
7. 内容范围、选择结果、版本和计时状态在聊天或内部记录维护。先保存并展示当前文件，再提出下一问题；一分钟从问题实际展示开始，不能从写文件开始计时。
8. 文件工具不可用时交付可复制的完整 Markdown 并说明未保存；工具失败时说明真实状态，不假称成功。

## 完整性与内容深度

- 文件保留实际完成的完整导读：标题与作者解读、摘要逐句/语义单元精读、结论逐段分析、实际比喻及边界、重点符号与参数含义表、全部正文精读、所选全部图表与子图、全部公式推导与作用、剩余阅读和各轮详细答疑、六项通篇总结。
- 内容深度依各阶段指南，不将逐句精读、推导或图表分析压缩成笔记要点。取消字数、公式数与答疑轮数上限，删除重复输出可引用已保存解释，但不能静默省略实质内容。
- 没有执行的附录阅读、图表详解或推导不伪装完成。用户跳过剩余阅读时，总结仍核对所需证据，文件不新增“已完整读完附录”的章节或记录。
- 所有关键数字、单位、指标方向、比较设置、数据集、条件与不确定性保留。定义式、设计式、经验式按性质解释，不能假造证明。
- 全部正文 Algorithm（含实验章）的输入输出、初始化、逐步执行、循环分支、状态更新及终止条件完整保存。可在 Second Time 后部的连续编号 Algorithms 区集中详解，正文对应位置链接到各条目；不另存算法文件，不以概述替代全部步骤。
- 样例仅参考格式和表达习惯，事实以当前论文核实，不复制样例错误或操作指令。默认骨架使用 assets/full-reading-template.md。

## 统一文件格式

- 文件以论文题名开头，随后直接进入已有实际内容的 First Time、Second Time、Overall Review。进行中仅保留已产生内容的分组，不提前放空章节；分组存在不等于阶段完成。默认完整流程结束时形成三组，用户明确跳过的阶段不补造分组或内容。不添加出处、作者/年份/版本信息行、论文链接、已读范围或流程说明开场。
- Title & Authors 中的作者名单、脚注与标题解读是实质内容，可以保留；禁止的是标题后额外添加一行作者/版本等元信息。
- First Time、Second Time 的章节和重要小节使用实际英文标题的连续编号二级标题，例如 `## 1.Abstract`，各组分别从 1 开始，句点后无空格。非英文原标题译为英文，中文释义和原章节编号放正文；进一步细分用列表或文字标签，不加三级标题。
- 图表四级标题只含编号及冒号，例如 `#### Fig1:`、`#### Table1:`。有原编号沿用；完全无编号时分别从 1 编号，混合时从同类已有最大编号后补号并说明。按原文出现顺序混合排列，附录原编号可保留 FigA1、TableS1。
- Algorithm 详解四级标题为 `#### Algorithm1:` 等仅含编号及冒号的形式，原题名写在正文；编号、紧凑排版及重点标题标红遵循 [Algorithm 详解指南](algorithms.md)，与 Fig/Table 分别维护编号。
- 首次保存就使用红色重点 `<font color="#ff0000">...</font>`，移除用于强调的星标；普通组织标签用纯文字，重点标签用红色。重点章节完整包住编号与标题；最重要图表只包住完整编号与冒号，理由放正文。没有图而有表时选表，没有图表不虚构重点。
- 图表标题与正文、同项段落之间、正文末尾与下一标题之间都无空行。普通小节标题与正文、同节段落之间无空行，正文末尾与下一标题之间留一行。
- Markdown 表格前留一行空行；表格后仍有说明正文时留一行，直接接下一图表标题时不补空行。公式块与代码块内部必要空行保留。
- 全文禁用原文页码、页数、范围与页码约定；定位用章节名、原章节编号、公式号或图表号。整理已有阅读文件时删除这些备注。
- 不嵌入原论文图片、截图、裁剪，也不复制完整实验表。图表保留完整文字讲解，表格可以用于解释变量或少量关键比较，但不能以复刻原表代替分析。
- 辅助 skill 不能加入破坏结构的 frontmatter、出处开场、PDF/原图嵌入、替代红色重点的 callout 或高亮。

## 正文到图表与算法精读的跳转

- 图表集中单独解读时，在正文对应段落或小节加入“图表对应”导航，例如 `图表对应：[Fig2 精读](#fig2)、[Table1 精读](#table1)`；多个相关图表逐一链接，不把所有图表无区别地挂在每个章节。
- 每个图表精读标题前紧邻设置无可见文字的唯一锚点，例如 `<a id="fig2"></a>`，标题仍为 `#### Fig2:` 或规定红色标题。锚点是紧凑排版的结构性例外；不额外添加空行、可见标题或标题说明。
- ID 由原图表类型及编号稳定生成，使用小写，例如 fig1、table2、figa1、tables1；在同一文件中不重复，不因章节调整或红色标签改变。导航优先指向显式 ID，不依赖不同渲染器对红色 HTML 标题自动生成同一 slug。
- 对应链接应出现在讨论该图表机制、实验、公式或结果的真实位置。补充阅读遇到无编号图表时，接续已有同类编号；正文和附录出现相同原编号时，保留可见原编号并以章节后缀区分锚点，例如 fig1-appendix，链接使用实际 ID。图表精读完成后可回填前面已读段落的链接；最终总结必要时也可链接相应精读。
- 只链接已存在的精读条目。尚未详解或用户拒绝图表详解时，不创建假目标、不强制执行被拒绝任务；暂保留普通原文编号，目标产生后再补链接。
- 检查每个链接目标存在、锚点唯一、显示编号与目标一致；有预览工具时测试跳转。不能把一个图表的引用链接到另一个图表或原 PDF 页码。
- Algorithm 集中区的每个标题前紧邻设置唯一锚点，例如 `<a id="algorithm1"></a>`；正文对应位置加入 `[Algorithm1 精读](#algorithm1)`。只链接已存在条目，算法号与目标一致；同编号附录算法以 `algorithm1-appendix` 等后缀区分锚点。正文实验章算法的链接附在实际已有的算法上下文中，不建立空章节。

## 公式与强调隔离

- 所有数学（含单个变量、参数范围、短式、长式）必须在红色标签、Markdown 加粗/斜体/高亮、HTML strong/b/em/i/mark 等强调节点之外。只强调文字标签；需要强调整句时分成公式前后两段文字强调，公式保持正常数学渲染。
- 不能写 `<font color="#ff0000">$0<\beta_i<1$</font>` 或 `**$x_t$**`；应写 `<font color="#ff0000">取值范围：</font> $0<\beta_i<1$`，或 `时间状态：$x_t$`。这些是字面格式示例，不是允许的违规输出。
- 检查红色重点正文、表格单元格、列表、标题和合并后的旧内容，不能只检查独立公式。修复时拆开外层强调，保持数学表达和行内/独立属性，不删除 LaTeX 内部具有数学意义的向量粗体。
- 数学若使用文字高亮颜色，在公式外部文字说明重要性，不能改成裸文本来绕过隔离规则；公式号和图表号定位仍保留。

## 文件数学与转换

- 保存前按 [SKILL.md](../SKILL.md) 的“原文公式符号”规则核对符号表、正文公式与中间推导：对应量均保留原文记号，不新增讲解辅助符号或临时别名。下方及模板中的通用数学示例只示范格式，实际讲解必须使用当前论文的公式与符号。
- Markdown 表格内的数学关系、条件概率或范数含竖线时，优先用 `\mid`、`\lvert`、`\rvert`、`\lVert`、`\rVert` 表达，避免裸 `|` 被表格解析器切成新单元格；渲染后核对列数与数学含义。

- 所有保存的阅读 Markdown 使用 `$...$` 段内数学，只有长公式使用两行独立 `$$` 围住。变量、函数、尺寸、短等式与短目标保持段内，句子不因公式拆断。
- 若内容先在聊天中写成 `\(...\)` 与独立 `\[...\]`，保存时按数学节点分别转换为 `$...$` 和独立 `$$`。保持原式内容、行内/独立属性和所在句子；文字强调在公式前关闭、公式后恢复，不能为了保留整句强调而把公式包进去。
- 不做全局字符替换；不能把普通美元金额误当公式，不能改 Mermaid 或其他代码块、代码示例、链接与字面转义内容。转换后核对括号、上下标、符号、条件与公式号。
- 任何阶段长文、完整聊天解读导出或合并文件都没有格式豁免；不能保存聊天定界符并承诺最终再转换。
- 聊天说明仍使用 `\(...\)`、`\[...\]`，不使用美元数学、红色标签或强调星标；文件格式不能反过来套用到聊天。

## 可编辑流程图与辅助 skill

- 在适合的阶段加入一张关键模型/算法 Mermaid 图，用 fenced mermaid、稳定 flowchart TD/LR，核对输入输出、分支汇合、跨模块信息、重复层数，以及必要形状、参数、掩码、残差和冻结部分。
- 不把层数当生成时间，不把条件分支画成所有情况必经；每条职责与连接有原文依据。说明合并或省略细节，理论/综述可用论证或概念图，无合适流程可以省略。
- 已有正确图不用收尾再复制。可渲染时实际检查解析、文字与连线，无法渲染时如实说明，不能声称已检查外观。工具不支持 Mermaid 时可附自行生成 SVG/PNG，并保留源码。
- anti-defensive-writing 是默认必用的写作 skill，遵循 [主规则](../SKILL.md) 的读取与应用要求；润色保留完整精读、原文顺序、公式符号、必要限定与证据，不将讲解缩成摘要。
- 其他本地可用的 Markdown/笔记 skill（如 obsidian-markdown）可按需联合使用；先读其 SKILL.md 和必要引用并告知用户。本 skill 的文件规则优先；这些可选辅助 skill 缺失不阻断保存。
- 已核实的相关本地笔记可用 wikilink，不虚构目标，不自动上传、发布或修改其他文件；未打开 Obsidian 时不声称已在其阅读视图验证。

## 收尾核对

- 当前文件路径与 reading_md_path 完全一致，未另建阶段或符号表 MD；重点符号与参数表简洁且足以支撑论文主线，未知项如实标记；其他符号在对应讲解处解释，不要求全部收录。当前文件覆盖全部实际解读和答疑，推导与图表没有因精简目标丢失；未读内容不填模板占位。
- 三个主分组、连续英文二级编号、图表四级编号与冒号、红色重点、空行与表格边界符合规则。
- 全部正文 Algorithm 已详细解释并保存在同一文件；集中区位于 Second Time 后部，四级编号与冒号、紧凑排版、正文对应链接和唯一锚点均已核对。
- 已默认应用 anti-defensive-writing 并完成文字检查，润色保留全部应讲内容、推导步骤与必要限定，事实和结论强度符合原文证据。
- 所有保存数学都在强调标记之外，使用正确美元定界符，转换保持内容且未碰代码块；无原文页码、出处开场、原图嵌入、完整实验表或模板占位。
- 数值、版本、指标、比较设置、训练/推理区别、证明条件与结论边界正确；Mermaid 和链接核对，正文的图表对应链接全部指向本文件存在且唯一的精读锚点。
- 总结追加完成后交付同一完整文件，不生成额外精简笔记，不重复整个文件到聊天中。
