# Algorithm 详解指南

正文存在 Algorithm、算法框或实质性伪代码时，在第二次阅读执行本指南。全部正文算法均须详细解释，包含正文实验章；此任务独立于图表和公式两个选择，不增加选择问题或数量阈值。附录和独立补充材料中的算法按剩余阅读或用户指定答疑范围处理。

## 清单与原文核对

- 清点当前版本全部正文算法，记录原编号、原英文题名、所在章节、步骤或原行号、阅读状态及详解锚点；按原文出现顺序处理，包括无编号算法。无算法时如实记录，不创建空详解区。
- 对照原文核对伪代码缩进、循环范围、分支归属、赋值顺序、终止条件及函数调用；文本提取只能作为线索。模糊或缺失部分标记待核实，不以常见实现补齐。
- Algorithm 单独清点，不因排版为表格而计入图表阈值；其中独立数学关系仍按原有公式口径清点，重复引用不另计。同一算法被多处引用时保留一份完整详解并回链。

## 每个算法的详解

1. 给出原算法编号与题名、所在章节，说明它解决的问题、在整体方法中的位置，以及属于训练、推理、优化或其他计算过程。
2. 解释输入、输出、参数、状态和初始化；必要时说明形状、单位、取值条件及原文定义位置。变量、函数名、索引和公式均沿用原文，不新增讲解辅助符号或别名。
3. 按原行号逐行或按逻辑块解释，覆盖每个有效步骤、循环、分支及返回路径。逐步说明读取什么、执行什么运算、更新哪个状态、为何按此顺序，以及结果如何传给下一步；不能仅翻译伪代码或概述整体思路。
4. 解释循环范围、采样或选择规则、停止条件、边界情形和关键依赖。将更新式、正文公式及模型模块与步骤对应；公式详推选否时仍解释执行所需的运算含义，系统性公式推导继续服从原选择。
5. 说明输出如何参与后续训练、推理或实验，以及原文支持的适用条件、正确性或复杂度结论。原文未提供时如实说明，讲解补充推理须标明依据；必要例子沿用原文符号并明确示例取值。

## 集中写入与正文跳转

- 全部详解写入固定 reading_md_path 的 Second Time 后部，使用连续编号英文二级章节，例如 `## 6.Algorithms`；编号接续实际已有章节，不另建算法笔记，不为每个算法暂停。
- 每项标题仅含英文编号和冒号，例如 `#### Algorithm1:`；原题名及定位写在正文。保留原编号；无编号条目按出现顺序补号，与已有编号混合时从已有最大编号后接续，注明导读补号并保持已有 ID 稳定。
- 标题前紧邻放置唯一无可见文字锚点，例如 `<a id="algorithm1"></a>`；在正文实际讨论该算法的位置添加 `[Algorithm1 精读](#algorithm1)`。正文实验章未整章精读时，只在算法相关内容处提供必要上下文和链接，不补造整章精读或空章节。
- 只链接已经存在的详解条目，必要时完成集中区后回填正文链接。附录出现相同原编号时保留可见编号，以 `algorithm1-appendix` 等后缀区分锚点，并使用实际目标 ID。
- Algorithm 条目沿用 Fig/Table 的紧凑排版、表格块边界与数学格式：标题下一行直接正文，段落及相邻条目之间不留空行。文件中的重点标题可写成 `#### <font color="#ff0000">Algorithm1:</font>`，数学保持在强调标记之外；聊天使用普通标题。

## 完成核对

- 核对已详解条目与正文清单，包括实验章算法和全部分支、循环及输出；原文缺失或步骤未核实处保留未完成状态。
- 核对所有正文算法链接目标存在且唯一，显示编号与目标相符；已保存完整详解后才交付本阶段文件并进入剩余阅读选择。
- 默认应用 anti-defensive-writing 润色讲解，保留完整步骤、原文符号、必要条件与证据；按 SKILL.md 的聊天和文件格式分别交付。
